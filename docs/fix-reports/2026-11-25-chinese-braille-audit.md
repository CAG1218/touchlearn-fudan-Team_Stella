# Fix Report - 函数触觉板盲文被 DeepSeek 判为“乱码”

日期：2026-11-25　版本：v0.4.x

## Bug 描述

用户把函数触觉板的盲文截图发给手机端 DeepSeek，DeepSeek 回复“乱码”，并给出一串拉丁字母。用户因此怀疑 Agent 生成的中文盲文本身是错的，要求联网核对中文盲文规范，并把所有功能生成的中文盲文改对。

## 问题根因

### 主因：解码方用错了表，不是点阵损坏

中文盲文是“声母 + 韵母 + 声调”的双拼制，每一方是一个拼音符号；DeepSeek 用英文字母盲文表逐格转写，才会得到 `pul dgnupgaiuuich mfmfiemmh` 这类无意义字母串。同一段点阵用中文盲文表读是通的，用拉丁表读必然不通。

这不是“AI 生成时随机画点”：点阵由 `cnbraille` 查拼音表后确定性编码，同一字符每次生成的点完全一致。仓库里已有逐字对照表和回归测试，可以直接复核。

### 次因：四个真实缺陷，已一并修掉

1. **对照表与实物点阵可能不一致**：`describe_text()` 自己走了一遍字符循环，不知道 `encode_text()` 新加的词间空方；对照表少一行“分词空方”，读表的人会把后一个词的首方当成前一个词的末方。
2. **词组分段过粗**：`PHRASES` 里把 `二次函数图像`、`六轴机械臂`、`末端执行器` 等跨词短语合成一条，最长匹配会吞掉词与词之间的空方，读起来像一长串没有停顿的音节。
3. **GF 0019 3.2.5 未实现**：声母自成音节后接韵母自成音节时（如“慈爱”），前一首节必须保留声调；旧实现会按“c 省阳平”把“慈”的声调省掉。
4. **零声母音节保调表有误**：旧表把 `yi4/er4/wo4/ye4/you4` 全部列为保调，导致“二”多印一个去声方。按规则 2.4，韵母自成的音节省去声；3.1 只对 `yī`（省一声）、`ér`（省二声）、`wǒ/yě/yǒu`（省三声）单独开口子。现在“二/亿/卧”都是单方。同时补上 3.2.6 原例“问”（`wen4` 保调），并把“再”从音节级保调改为按字保调，`在` 不再被误留声调。
5. **中文标点用了错误的点表**：旧表除逗号外基本是英文/自造点位，句号、问号、感叹号、冒号、分号、括号都不对。已按 GF 0019 §8 改为中文标点表（。= ⠐⠆、？= ⠐⠄、！= ⠰⠂、：= ⠤、；= ⠰），并支持“——”“……”这类双标点只写一次；点表的值从“单方”改为“方序列”。
6. **“的平方”被粘成一个词**：回退分词器没有虚词表，`的` 与 `平方` 连写中间没有空方。数学式里的这个空方属于分词问题，不是音节问题。

另外，`docs/tactile_spec.md`、`docs/positioning.md`、`docs/standards/evidence.md` 中仍写着“当前使用 UEB、尚未实现 GF 0019”，与代码实际行为相反，已同步更正。

## 尝试记录

### 尝试 1：怀疑“次”漏了去声

- 结果：不改
- 原因：GF 0019 的去声省写只适用于 `b d l g k j x zh sh z s`；`c` 只在阳平省写，所以 `ci4 = ⠉⠆` 是对的。

### 尝试 2：怀疑“再”不应保留声调

- 结果：不改
- 原因：规则 3.2.6 明确以汉字“再”为例，说明需要声调符号区分音义时不省写。

### 尝试 3：直接用英文字母表“纠正”点阵

- 结果：否决
- 原因：会把正确的中文双拼改成真正的乱码；必须先确定读表方式，再谈点阵对错。

### 尝试 4：实现全部简写（的/么/你/他/她/它）

- 结果：暂不实现
- 原因：简写规则在正式出版物中启用，但考试制卷等场景明确“不含简写”；在无法用权威表逐格复核简写点位前，按全拼输出更安全，读出来仍然唯一。已在文档中声明这一边界。

### 尝试 5：保留“y=x的平方-2x-3”

- 结果：改为“y=x平方-2x-3”
- 原因：虚词表缺失时，“的”会被粘到“平方”上，缺少分词空方；去掉“的”后语义不变，也避免输出不合规的分词。

## 最终方案

1. `cnbraille` 增加 `_units()` 统一分词，`_word_cells()` 在词内应用 3.2.5；`encode_text()` 与 `describe_text()` 共用同一套边界，对照表逐行等于实物点阵。
2. `PHRASES` 拆开跨词短语（`二次函数` + `图像`、`六轴` + `机械臂`、`末端` + `执行器` 等），恢复词间空方。
3. `braille_map.md` 表头改为《国家通用盲文方案》，新增“每方是声母/韵母/声调，不是英文字母”的解码提示，并列出“分词空方”行。
4. 打印说明、README、`docs/tactile_spec.md`、`docs/positioning.md`、`docs/standards/evidence.md` 统一标准名称、尺寸和已知边界。
7. 新增回归测试：`ci4/er4/shu4/wei4` 精确点位、零声母各声调、`再`/`在` 的区别、3.2.5“慈爱”、对照表与点阵逐格相等、`触摸学习`/`六轴机械臂` 恰好一个词间空方。

## 经验教训

“乱码”要先问“谁在用哪张表读”。中文盲文和英文盲文共用 6 点格，但符号语义完全不同；任何外部模型的判断都必须回到标准表逐格复核，不能拿拉丁字母串反推点阵错误。

## 第二轮（2026-11-26）：简写、数学盲文、分词兜底与读校方案

第一轮末尾“仍然不能宣称的内容”里，关于简写、数学符号和分词的三条，在这一轮分别转为“已接入”“已接入（失败关闭）”“已扩容并让风险可见”；“没有盲人实测”这一条无法靠代码解决，改为交付一套可执行的读校方案，状态仍写“未执行”。

### 1. GF 0019 §11 定字简写接入生产路径

- `cnbraille.SHORTHAND`：的 ⠙、么 ⠍、你 ⠝、他 ⠞、她 ⠞⠁、它 ⠈⠞。
- `SHORTHAND_BLOCKED_BEFORE_ZERO_FINAL = {"的","么","你","他","它"}`：按 §11.2，这五个字后面接韵母自成的音节时回到全拼；她不在阻断名单内，按规则照常简写。
- 简写只对读音为 de / me / ni / ta 的这六个字形生效，`目的`（mùdì）、`的确`（díquè）不会被误简化。
- 回归测试：`怎么` 末方必须是 ⠍；`怎么样` 因后接零声母“样”改回两方全拼（m 声母恰好也是 ⠍，所以用“占两方且第二方是 e 韵母”判定，不能只断言点位不在）；显式写全声调时禁用简写。

### 2. GB/T 18028-2010 数学盲文接入函数板

- `mathsymbols.py`：数号 (3,4,5,6) 置于每个数字前；大写 ⠠(6)、小写 ⠰(5,6)；`+` 235、`−` 36、`×` 236、`÷` 256、`=` 2356、点乘号 (3)、小数点 (2)。
- 失败关闭：括号、乘方号、函数号等没有可核实点位的符号不猜点形，`MathLabelError` 抛出后整行省略，并同时写构建警告和 `skip_equation_braille` trace，板面不会出现自造点阵。
- `x²` 按“乘方号未核实”处理，改写为 `x·x`。点乘号比乘号窄，`y=x·x-2x-3` 共 19 方 128.4 mm，落在 A5 的 136 mm 可用宽度内。

### 3. 标题与解析式分行

- 标题只保留汉字（`_han_label`）：`二次函数 y=x²-2x-3 图像` → 标题 `二次函数图像`，解析式另行排版。
- 原因：`²` 既不是汉字也没有可核实的数学点位，混进标题会让整行标题盲文被丢弃（`'²'.isdigit()` 为真，旧的 `_chinese_label` 拦不住）。

### 4. 排版回归：新增解析式行撞上纵轴标签

- 现象：加入 `equation_braille` 后，A4/A5 函数板全部变成 `printable: false`，规则 `tactile.annotation_distance 1.81 mm`。
- 根因：`equation_braille` 建在 `margin + 16`（y 22–28.8），`plot_top` 仍是 `margin + 24`；纵轴标签“纵轴”从 30.6 开始，与解析式行只隔 1.81 mm，低于 2.00 mm。更关键的是放置纵轴标签时 `equation_braille` 没进 `obstacles`，放置器根本不会避让。
- 修复：把 `equation_braille` 加进 `obstacles`；`plot_top` 下移到 `margin + 26`，给页眉三行留出 3.2 mm 净纸。实测 A4、A5 均为 `tactile.annotation_distance 2.40 mm PASS`，`printable: true`。

### 5. 分词词典扩容与未核验词提示

- `PHRASES` 94 → 175 条，补入场景模板、图例和页脚真实出现的词（其它/标记、四根/柱子、类别/编号、读取/输入、细胞核/细胞膜、坐标轴、直角三角形、左侧/右侧、太阳/地球/月球等），并修正 `边长 bian1 chang2`、`转动 zhuan4 dong4`、`部分 bu4 fen5` 的读音。
