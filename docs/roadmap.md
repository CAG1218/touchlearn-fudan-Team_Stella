# 路线图

路线图按"证据强度"排序，而不是按功能听起来是否酷。v0 已经把链路跑通，接下来最缺的是**真实打印**和**真实用户**，不是更多案例。

## v0.1.0（当前）

已完成：

- 语义契约、手写校验和 JSON Schema；
- 两个确定性布局引擎；
- 3×5 笔画字体、UEB 盲文、耳切三角化、棱柱与二进制 STL；
- 可打印性门禁（边距、线宽、标签、二维码区、浮雕、水密）；
- 两个案例的完整产物、47 项测试、CI；
- 架构、触觉规格、运行、盲测、提交文档；
- A6 图例打印 PDF、试运行 TTS 和本地播放页。

明确未完成：

- 实体打印；
- 盲人用户测试；
- 公开音频托管与二维码贴纸；
- A6 触觉图例板；
- 任意图片的自动语义提取。

## 下一阶段（比赛提交前，按优先级）

### P0：实体打印一块板

**为什么**：STL 水密不等于能打印。首层、浮雕高度、盲文拉丝、翘边都只能在机器上暴露。

**做什么**：

1. 用 `dist/robot-arm-6axis/model.stl` 切片，记录喷嘴、层高、温度、速度；
2. 打印一块，拍照记录失败点；
3. 用游标卡尺量板厚、浮雕高度、盲文点径；
4. 把实测值写进 `docs/tactile_spec.md`，不要只写"建议值"。

**验收**：板厚 3.0 ± 0.2 mm，浮雕 0.8 ± 0.15 mm，盲文点无连丝，手指可连续滑过连杆。

### P0：完成 3–5 人盲测

**为什么**：没有用户证据，"可触摸"只是设计意图。

**做什么**：按 `docs/blind_test_protocol.md` 执行；先蒙眼试运行，再正式测试；记录失败类型和原话。

**验收**：至少 3 名参与者完成核心任务；报告里同时有通过率、失败案例和局限。

### P1：音频上线

**为什么**：二维码现在只是预留区，扫码听不到东西。

**当前进度**：试运行 TTS 和本地播放页已完成（`fabrication/audio/`）；公开托管、真人录音和二维码贴纸尚未完成。

**做什么**：

1. 用 `audio.txt` 做 TTS 或真人录音；
2. 托管到一个稳定页面，页面同时提供文字稿；
3. 用 `scripts/make_qr.py` 生成二维码；
4. 三台手机、两种扫码 App 测试；
5. 把二维码放进演示物料，但不改 STL（贴纸或后印刷）。

**验收**：扫码到播放 ≤ 5 秒，外放清晰，页面无登录墙。

### P1：A6 触觉图例卡

**为什么**：当前图例卡是打印件，不是触觉件；如果陪同者不在场，编号到名称的映射只能靠记忆。

**做什么**：为 A6 写一个 2 mm 薄板布局器，复用现有图元和检查；或者在图例卡上直接压印盲文名称。

**验收**：8 个编号的盲文名称可独立摸读；与 A5 板编号一致；通过边距和线宽检查。

### P2：第二个函数案例

**为什么**：验证 `cartesian_plot` 不是只为一条抛物线写死。

**做什么**：增加一个不同系数、不同定义域的案例（例如 `y = -0.5x² + 2x + 1`），确保顶点、根、对称轴都由系数计算，而不是硬编码。

**验收**：新案例自动生成正确关键点；不需要改布局引擎。

## 中期（比赛后）

### 上游语义提取

做一个独立的 `extract` 阶段：输入教科书照片或手绘草图，输出符合本契约的 JSON。视觉模型只负责"有哪些元素、关系是什么"，布局和几何仍走确定性编译。验收标准不是"看起来像"，而是"元素和关系与人工标注一致率达到阈值"。

### 更多布局引擎

按教学场景优先级：

1. 电路图（节点—边，但需要避免交叉）；
2. 力学受力图（箭头、角度、合力）；
3. 几何证明图（三角形、辅助线、全等标记）；
4. 表格/流程图（层级和顺序）。

每增加一个引擎，必须同时增加一个反例测试和一个 `trace` 决策说明。

### 材料与工艺

- 对比 PLA、PETG、树脂和 swell paper 的触感与耐久；
- 测试不同浮雕高度（0.5 / 0.65 / 0.8）对识别率的影响；
- 评估双面板、可更换卡片、磁吸拼接的可行性；
- 做 50 次触摸和清洗后的磨损测试。

### 教学协作

与特教学校或盲校老师合作，把图放进真实课程单元，观察学生是否能在讲解后独立复述结构。比单次实验室测试更有价值，也更难做。

## 非目标

- 不做通用 3D 模型生成器；
- 不做在线图库平台（至少 v1 前不做）；
- 不做需要账号和云端的核心编译；
- 不用生成式模型替代可检查的几何；
- 不承诺"任意图片一键出图"，直到上游提取有可量化验收。

## 风险登记

| 风险 | 影响 | 应对 |
|---|---|---|
| 打印机精度不足，盲文粘连 | 高 | 先打小样，调温度和回抽；必要时增大点距 |
| 盲测招募延期 | 高 | 先做蒙眼试运行；如实标注未完成，不编数据 |
| 音频托管链接失效 | 中 | 用稳定页面 + 文字稿；二维码指向页面而非临时文件 |
| 只有两个案例，显得单薄 | 中 | 把两个案例做深，讲清楚取舍；路线图说明扩展方式 |
| 评委质疑"描图也能做" | 中 | 用 `trace.jsonl` 和系数驱动证明语义重建，不靠口头 |
| 代码只有一个人能维护 | 中 | 契约、测试、文档齐全；CI 在 3.10/3.12 上跑 |
| 触觉图被误用为教学替代品 | 低–中 | 文档明确"辅助工具"，不替代教师讲解和真实实验 |

## 完成定义

一个版本只有同时满足以下条件才算完成：

1. 两个案例端到端构建 PASS；
2. 测试全绿；
3. `dist/` 与源码同步；
4. 文档更新；
5. 至少一项新增的真实世界证据（打印、盲测、教学试用或用户访谈）。

第 5 条是 v0 之后每个版本必须补的，不然只是在代码里打转。
