# 盲测方案

这份文档是 v0 的测试计划，**尚未执行**。仓库里没有任何"盲人用户已验证"的结论。做完成测试后，把原始记录、统计和结论补进本文，并同步更新 README 的"当前状态"。

## 1. 要回答的问题

1. 用户能否在无人提示的情况下找到定向缺口，并说出图的方向？
2. 用户能否沿机械臂从基座摸到末端，正确数出关节数量，并区分腕部三个小圆点？
3. 用户能否在函数图上找到顶点、两个根和对称轴，并描述曲线开口方向？
4. 编号盲文是否可读？数字与图例卡的对应是否成立？
5. 扫码音频是否能在真实手机上顺利播放，讲解顺序是否与触摸顺序一致？
6. 哪些失败来自语义（图本身不对）、布局（位置不对）、触觉（摸不出来）或音频（说法不清）？

## 2. 伦理与边界

- 参与自愿，可随时停止，不需要理由；停止不影响任何补偿。
- 测试前用口头说明和可触摸的样例解释流程，取得口头或书面同意。
- 不拍摄面部视频；如需录像，只拍手部与桌面，并单独征得同意。
- 记录表只写 participant code（P1、P2…），不写姓名、联系方式、病历。
- 不在测试中收集与任务无关的个人信息。
- 不把"盲人用户"当作单一群体：盲文水平、残余视力、使用触觉图的经验都会影响结果，分析时要区分。
- 测试用的板子边缘要倒角、无毛刺；测试前用湿巾擦拭，不用刺激性清洁剂。
- 如果参与者感到手指疲劳或不适，立即停止。

## 3. 参与者

目标 3–5 人，尽量覆盖：

- 至少 2 名以盲文为主要阅读方式的全盲用户；
- 至少 1 名有残余视力、但不依赖视觉读图的低视力用户；
- 至少 1 名有触觉图使用经验者（例如学过盲文数学或摸过校园平面图）；
- 如果条件允许，请 1 名定向行走与 mobility 教师作为观察者，不替代用户完成任务。

排除：手指有开放性伤口、近期手部手术、无法完成 20 分钟触摸任务者。不要为了凑人数降低标准。

先找 1–2 名视力正常但蒙眼的同事做**试运行**，只用于发现流程问题，不计入正式样本。

## 4. 材料

- A5 机械臂板、A5 函数板，各 3 份（防止打印瑕疵）；
- A6 图例卡两张；
- 已贴二维码并链接到音频的手机 1 台（参与者自己的手机更真实，但需提前确认能扫码）；
- 备用手机 1 台，外放音箱 1 个；
- 计时器、记录表、笔；
- 眼罩（仅用于蒙眼试运行）；
- 湿巾、垫布；
- 参与者信息与同意书（单独存放，不进仓库）。

## 5. 测试流程（每人约 30–40 分钟）

### 0. 欢迎与同意（5 分钟）

说明：我们测试的是图，不是你；没有标准答案；可以随时停；我们记录的是图能不能被摸懂。签署同意书，分配 participant code。

### 1. 自由探索（5 分钟）

把机械臂板放在桌上，缺口朝左上，不提示方向。说：

> "这是一块触觉图。请先随意摸一摸，然后告诉我你摸到了什么。"

记录：第一反应、是否主动找方向、是否发现缺口、是否把板子拿反。

### 2. 定向任务（2 分钟）

> "请找到这块板的左上角，并确认图的方向。"

记录：是否找到缺口、用时、是否需要提示。若 60 秒未完成，给一次最小提示："注意边缘有没有一个缺口。"

### 3. 机械臂结构任务（8 分钟）

依次要求：

1. 找到基座（编号 1）；
2. 沿连接线摸到末端夹爪（编号 8）；
3. 数出沿途经过的关节数量；
4. 找到腕部放大板（编号 7），说出里面有几个小圆点；
5. 从下到上摸这三个点，判断它们是否等距。

记录：成功/部分成功/失败、用时、错误类型（漏掉关节、把连杆当关节、把腕部板当成独立零件等）。

### 4. 函数图任务（8 分钟）

1. 找到曲线的最低点（顶点，编号 1）；
2. 找到曲线与横轴的两个交点（编号 2、3）；
3. 找到对称轴，并说出了解它的标注；
4. 描述曲线从哪边上升、哪边下降；
5. 找到原点 `o` 和坐标轴 `x`、`y`。

记录：坐标定位是否准确、是否把对称轴当成曲线、是否能区分两个根。

### 5. 编号与图例任务（3 分钟）

随机报三个编号（例如 4、7、2），让参与者在板上找到，并在图例卡上匹配名称。记录：编号识别率、图例卡是否可读、是否需要把图例卡转方向。

### 6. 扫码音频任务（5 分钟）

让参与者用自己的手机扫码（或由陪同者扫码后外放），从头听一遍讲解，同时摸图。记录：

- 扫码是否成功、打开页面耗时；
- 音频是否清晰、语速是否合适；
- 讲解顺序与触摸顺序是否一致；
- 是否出现"听到某个词但图上摸不到对应物"的情况。

### 7. 访谈（4 分钟）

半结构化问题：

- 哪一部分最容易迷路？为什么？
- 哪个编号最难找？
- 如果只能改一处，你会改什么？
- 这块图你会愿意在课堂上用吗？为什么？
- 0–5 分，整体可用性打几分？

不要诱导，不要追问"是不是很好"。记录原话。

## 6. 记录表字段

每个任务一行：

| 字段 | 说明 |
|---|---|
| participant | P1… |
| case | robot / quadratic |
| task | orientation / chain / wrist / vertex / roots / symmetry / legend / audio |
| result | success / partial / fail |
| time_s | 秒 |
| errors | 自由文本，按类型归类 |
| hints | 提示次数与内容 |
| quote | 原话（去标识） |
| notes | 观察到的动作，例如"用食指沿边滑动" |

## 7. 判定标准

v0 不追求统计显著性，n=3–5 只做描述性分析。建议的通过线：

- 定向：≥ 4/5 能在 30 秒内找到缺口；
- 机械臂链路：≥ 3/5 能独立从基座摸到末端，关节数误差 ≤ 1；
- 腕部：≥ 4/5 能说出 3 个点，且认为可区分；
- 函数关键点：≥ 3/5 能独立找到顶点和两个根；
- 编号：≥ 4/5 能正确匹配 3 个随机编号中的至少 2 个；
- 音频：≥ 4/5 能顺利播放，且认为讲解顺序与触摸顺序一致；
- 整体可用性：中位数 ≥ 3.5/5，且无人给出 0–1 分。

任何一条不达标，不掩盖，写进结论并进入下一轮修改。

## 8. 失败分类与迭代

把问题归到四层，避免"一改就全改"：

| 层 | 例子 | 修改位置 |
|---|---|---|
| 语义 | 关节数量标错、根算错 | `examples/*/diagram.json`、布局引擎 |
| 布局 | 标签太挤、腕部板太小 | `layout.py` 坐标与尺寸 |
| 触觉 | 线太细、盲文点粘在一起 | 线宽、点径、浮雕、打印参数 |
| 音频 | 讲解顺序与触摸顺序不一致 | `audio.steps` |

每轮只改一个层的主要变量，重新构建、重新检查、再找新参与者或同一参与者做对照。同一参与者重复测试要记录学习效应，不能把第二次更快直接归因于改版。

## 9. 停止规则

- 参与者主动要求停止；
- 连续两个任务失败并表现出明显挫败；
- 手指疼痛、皮肤破损或不适；
- 设备故障导致任务无法继续。

停止后不追问原因，记录停止点，按实际完成的任务分析。

## 10. 结果怎么写

测试结束后在本文追加：

1. 参与者构成（匿名）；
2. 每个任务的通过率与用时中位数；
3. 典型错误与至少 3 条原话；
4. 四层分类的问题清单；
5. 哪些问题已经修，哪些留到下一版；
6. 明确的局限：样本小、地区单一、未做长期耐久测试。

不要用"用户都很喜欢"这类无法核对的总结替代数据。一个用户说"能摸出来"不等于产品可用。

## 11. 时间安排（建议）

| 阶段 | 时间 |
|---|---|
| 试运行与流程修订 | 1 天 |
| 招募与排期 | 3–5 天 |
| 正式测试（3–5 人） | 2–3 天 |
| 整理与改版 | 3 天 |
| 复测（可选，1–2 人） | 1 天 |

如果比赛截止前无法完成正式测试，就在提交材料里写"方案已就绪，尚未执行"，不要用试运行数据冒充正式结果。
