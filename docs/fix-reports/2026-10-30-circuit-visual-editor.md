# Fix Report - 自带示例只有文字、电路不可编辑、上传电路图无法回到编辑流程

> 历史记录：本报告写于访问码阶段。访问码已在后续版本被手机号/邮箱验证码账号系统取代，文中“访问码鉴权”对应的行为现在由登录鉴权承担；报告其余内容保持当时状态。

## Bug 描述

用户反馈，首页四个自带示例仍然只是文字卡片，无法直接编辑：

1. “电路图”示例点开后只有一段文字描述，没有预置的元件位置和导线；
2. 用户不能在图上选中、拖动、替换、删除元件，也不能改开关状态；
3. 用户输入“把开关闭合”“把灯泡换成电阻”这类自然语言后，系统没有把它落到电路图上；
4. 用户上传一张电路图图片后，系统没有识别出这是电路图，也没有进入同一个可视化编辑流程；
5. 示例缩略图只是文字，用户点开前无法判断会得到什么图。

继续审计时还确认了以下同类问题：

- 显式传入空电路时，`normalize_circuit` 会静默补成内置的四元件串联电路，等于凭空发明用户没有画过的元件；
- 图片识别模型返回空元件、空 JSON 或非电路图片时，旧实现会硬失败，或者在宽松路径下落到默认电路；
- 草稿卡上的“编辑图形”打开的是内置电路，不是当前草稿自己的电路和标题；
- 触摸拖动被系统取消（`pointercancel`）时，仍会把最后一次移动提交到服务端；
- 没有可编辑场景时，兜底模板列表仍然只有文字，没有缩略图和“可编辑”标识；
- 图片已经由视觉模型读过时，路由器的“仅按文件名判断”免责声明仍会出现在草稿备注里，和识别结论自相矛盾。

## 问题根因

### 1. 示例是“提示词模板”，不是“可视状态”

旧示例只携带一段完整提示词，点击后进入分析流程。文字提示可以描述电路，但不包含任何可编辑的元件、位置、导线或开关状态，因此用户没有可操作的起点。

### 2. 电路图是静态图元，没有语义模型

旧电路模板把电池、开关、电阻、灯泡画成一组固定线段。图能打印，但：

- 不知道哪一段是电池、哪一段是导线；
- 移动一个元件后，导线不会跟着走；
- 删除元件后，回路可能断开；
- 浏览器无法把“拖动”翻译成有意义的电路修改。

### 3. 浏览器端没有权威几何

如果让前端自己改 SVG 坐标、自己补导线，拖动角度稍有偏差就会产生悬空线；而且屏幕上看到的图和最终 STL 使用的图是两套数据。必须让服务端成为唯一几何权威：浏览器只发“把开关移到下方”这类语义操作，服务端重新编译电路、重画导线、返回新 SVG。

### 4. 图片识别没有独立入口

旧图片路径走通用场景生成，模型即使认出电路，也只返回普通图块。没有“这是不是电路图”的判断，也没有“识别失败时回到手动搭建”的明确出口。

### 5. 归一化默认值越过了“用户明确输入”的边界

`normalize_circuit` 为了兼容不完整模型输出，会在元件为空时载入默认串联电路。这个默认值对“模型少给字段”是合理的，但对“用户明确传入空电路”“识别模型返回空元件”是有害的：它会把失败伪装成成功，并凭空生成四个元件。

### 6. 前端只处理了 `pointerup`，没有区分取消

`pointercancel` 与 `pointerup` 共用一个收尾函数，导致系统手势、来电、切后台等取消事件也会提交移动。

## 尝试记录

### 尝试 1：把示例改成只填入输入框

- 结果：部分成功，但不解决问题
- 原因：这解决了“点一下就自动发送”，但示例仍然是文字；用户要的是预置好的可编辑图像。

### 尝试 2：在示例卡里画一张静态电路 SVG，点开后进入文字说明

- 结果：失败
- 原因：图只是缩略图，点开后没有元件级编辑能力，仍然无法满足“哪个位置是什么元件、导线怎么连”。

### 尝试 3：让浏览器直接拖动 SVG 图元并自己补线

- 结果：失败
- 原因：导线需要沿回路重新走线，前端补线会和打印几何漂移；元件被拖到角上时还会出现悬空连接。最终改为服务端权威编译。

### 尝试 4：用通用场景编辑器编辑电路

- 结果：失败
- 原因：通用场景只知道“图块”，不知道“电池/开关/电阻”；两个带标签的方框也可能被误判成回路。最终增加电路语义层，只有真正带导线的场景才提升为电路。

### 尝试 5：模型返回空电路时回退到默认四元件电路

- 结果：失败
- 原因：这正是“凭空发明元件”的来源。新增测试固定住该行为后，确认 `generate_scene` 中把空电路赋成 `{}` 仍会进入 `normalize_circuit` 并被补成默认电路。最终改为 `None`，并在预览、编辑、识别、分析四个入口分别拒绝显式空电路。

### 尝试 6：图片识别失败时直接抛错

- 结果：失败
- 原因：用户上传一张抛物线图或模糊照片时，整个流程被一个 400/500 阻断。最终改为：非电路、空元件、模型返回不可解析内容都返回 `kind: "scene"` 的诚实结果和下一步建议；只有没图、没配置视觉模型、真实 API 故障才抛错。

## 最终方案

### 1. 电路语义模型与确定性编译器

新增 `src/touchlearn/agent/circuit.py`：

- 元件类型：`battery`、`switch`、`resistor`、`lamp`、`ammeter`、`voltmeter`、`motor`；
- 每个元件用 `side`（top/right/bottom/left）+ `offset`（0–1）描述位置，开关额外有 `state`；
- 回路用 `loop: [x0, y0, x1, y1]` 描述；
- 导线由 `_wire_segments()` 根据元件位置自动生成，永远闭合，不保存手工导线坐标；
- `apply_op()` 支持移动、添加、删除、替换类型、开关状态、改标签、旋转、缩放/平移回路、调整阅读顺序；
- `parse_circuit_instruction()` 离线解析常见中文指令（“把开关闭合”“加一个电流表”“把灯泡换成电阻”“删除电阻”“把开关移到左上角”“把回路放大”等）；
- 离线解析不中时，才调用文本模型；模型返回空元件会被拒绝，不会回退到默认电路。

### 2. 服务端权威的 SVG 预览与编辑服务

新增 `src/touchlearn/agent/scene_svg.py`：

- 直接使用 A5 真实板面坐标（148×210 mm）和内容框 `(8, 24, 132, 142)`；
- 每个图块输出 `data-block-id`、`data-kind`、`data-label`、`data-label-zh`；
- 输出 `.block-hit` 命中区和 `.block-outline` 选中框；
- 编号徽标只在 `show_names=True` 时输出，且 `pointer-events="none"`，不会挡住拖动；
- 导线块统一 `data-kind="wire"`，前端禁止选中/拖动。

新增 `src/touchlearn/agent/scene_edit.py`：

- `preview_scene()`：电路或普通场景 → 规范化 → 编译 → 返回 `svg`（带编号）和 `svg_plain`（不带编号）；
- `edit_scene()`：应用一个语义操作或一句自然语言；
- `recognize_circuit_image()`：专用视觉识别，只有真正电路才返回 `kind: "circuit"`；
- 所有入口先校验显式空电路，空电路返回 400，而不是静默补默认值。

服务端新增 `POST /api/scene-preview`、`POST /api/scene-edit`、`POST /api/scene-recognize`，以及带 `?crop=loop` / `?crop=content` 的模板缩略图路由。

### 3. 移动端可视化编辑器

- 首页四个示例卡改为真正的视觉入口：函数曲线内联 SVG、机械臂内联 SVG、电路服务端缩略图、上传卡；
- 电路缩略图使用 `?crop=loop`，只截元件回路，手机上也能看清符号；
- 全屏编辑器 `#sceneEditor` 包含画布、状态栏、元件检查器、元件面板、自然语言输入、上传按钮、恢复默认按钮；
- 拖动只改本地视觉位置，`pointerup` 时把 `move_component` 语义操作发给服务端；`pointercancel` 直接放弃本次移动；
- 服务端返回新 SVG 后整体替换画布，导线随元件位置重画；
- 草稿卡上的“编辑图形”现在带入当前草稿的电路/场景和当前标题，不再默认打开内置电路。

### 4. 上传电路图识别

- 编辑器内和聊天上传都走 `recognize_circuit_image()`；
- 识别成功：返回 `kind: "circuit"`、元件列表、SVG、置信度、需要用户确认的问题；
- 识别为非电路：返回 `kind: "scene"`、`editor: "none"` 和原因，不再阻断后续普通场景流程；
- 模型返回空 JSON、空元件、不可用结构：同样返回诚实的“未识别出电路”，并建议换图或手动搭建；
- 只有“没有收到图片”“没有配置视觉模型”“真实 API 故障”才抛错。

### 5. 构建以电路为唯一事实来源

`TouchLearnAgent._build_scene()` 在存在 `fields.circuit` 时：

- 重新 `normalize_circuit()`；
- 用 `circuit_to_scene()` 重新编译场景；
- 覆盖旧 `fields.scene`；
- 写出 `circuit.json` 到作业目录。

这样即使前端传了旧的场景快照，最终 STL 仍按用户确认的电路重新生成，标题覆盖也能落盘。

### 6. 空电路与前端细节守卫

- `preview_scene` / `edit_scene`：显式空电路 → `SceneEditError`；
- `generate_scene`：模型空电路 → `raw_circuit = None`，并记录“已忽略这套电路结构”；
- `_analyze_scene`：显式空电路 → 忽略并追加问题，不回退默认电路；
- `_llm_edit_circuit`：模型空元件 → 明确报“修改未应用”；
- 图片识别：空元件 → `kind: "scene"`；
- 拖动取消 → 不提交移动；
- 兜底模板列表 → 带缩略图和“可编辑”标识；
- 图片存在时 → 过滤路由器的“仅按文件名判断”备注，避免和视觉识别结论冲突。

## 经验教训

1. **默认值只能补“缺失”，不能补“明确为空”**。`normalize_circuit` 的默认电路对缺字段是兼容，对空列表就是发明数据。显式空输入必须在入口处拒绝。
2. **把“画图”拆成“语义模型 + 确定性编译器”**。只要导线由元件位置推导，拖动就不可能产生悬空线；屏幕、SVG、STL 也自然保持一致。
3. **失败要诚实**。识别不出电路时返回“不是电路/没识别出元件”，比偷偷载入默认四元件电路更可信，也不会让用户打印出一块错误的板子。
4. **前端只发意图，后端负责几何**。浏览器发 `move_component`，不发坐标补丁；这样移动端手势、桌面拖动和自然语言修改走同一条确定性路径。
5. **测试要覆盖降级分支**。这次真正抓到 bug 的不是“识别成功”用例，而是“模型返回空电路”用例；正常路径早就通过了。

## 补充：为什么页面显示“未知接口”（2026-10-30）

### 现象

在 `http://127.0.0.1:8769` 打开首页，点击“串联电路 · 可编辑”，编辑器画布和底部状态栏都显示“未知接口”。

### 根因

不是编辑器代码问题，而是**进程陈旧**：

- 8769 上的 Python 进程启动于 2026/10/29 19:18:43；
- `/api/scene-preview`、`/api/scene-edit`、`/api/scene-recognize` 是 2026/10/30 01:45 才加入 `server.py`；
- 静态文件（`index.html`、`app.js`、`styles.css`）每次请求都从磁盘读取，所以界面是新的；
- 已导入的 Python 模块留在内存里，不会热更新，旧进程对三个新接口一律返回 404 `{"error": "未知接口"}`。

### 处理

1. 停止占用 8769 的旧进程（需用户确认，停进程属于不可逆操作）；
2. 在项目根目录重启：
   ```bash
   python scripts/run_agent.py --port 8769 --no-browser
   ```
3. 验证：`POST /api/scene-preview` 应返回 `{"ok": true, "kind": "circuit"}`，而不是 404。

本次先用 8771 端口起了加载最新代码的新服务，接口与模板缩略图均已验证通过。

### 经验

**改了后端代码就必须重启服务**，只看页面是否变新会误判。排查“未知接口”时先比对 `server.py` 的修改时间和进程启动时间，比读前端代码更快。
