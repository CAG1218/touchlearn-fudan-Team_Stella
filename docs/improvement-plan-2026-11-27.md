# TouchLearn 智能体改进评估（2026-11-27）

本文回答一个问题：现在的智能体还有什么该改？结论按“风险 × 决赛收益”排序，分成**已经改完**、**决赛前还该做**、**决赛后再做**三档。所有判断基于当前仓库代码，而不是设想。

## 0. 一句话结论

**能力链路已经完整，短板不在“能不能做”，而在“出错时是否可控、出错后是否可查、盲人用户是否能独立完成全流程”。** 决赛前只做低风险体验与可观测补丁；队列、模块化、评测平台这类结构性改动放到赛后，避免在两周内把能跑的系统改坏。

## 2. 盲人模式：离 Siri 还差什么

### 2.1 现状盘点

已有：服务端统一话术、`SpeechRecognition` 语音输入、`speechSynthesis` 播报、语音栏重听/帮助/关闭、登录页语音引导、草稿确认（“开始生成”）、错误与网络降级话术、`prefers-reduced-motion`、44 px 触控目标、`aria-live` 区域。

本轮补上：语速、停止、去重、焦点可见、跳过导航、对话框焦点陷阱、构建进度播报、错误播报。

### 2.2 还缺的（按优先级）

| 优先级 | 缺口 | 影响 | 建议做法 | 工作量 |
|---|---|---|---|---|
| P1 | 语音指令覆盖有限 | 只能表达生成需求，不能“换 A4”“读一下合规报告” | 扩展 `/api/voice/interpret` 意图：换纸、重听报告、打开打印说明 | 1–2 天 |
| P1 | 没有“读屏模式”与“自建语音”二选一 | VoiceOver 用户与自建语音可能互相打断 | 检测 `navigator.userAgent` 不足；改为设置项“使用系统读屏，关闭内置语音” | 1 天 |
| P2 | 无震动/声音提示 | 听障+视障、嘈杂环境 | `navigator.vibrate` 在阶段切换时短震 | 0.5 天 |
| P2 | 无离线语音 | 断网时依赖系统 TTS，音色不可控 | 保持系统 TTS，不引入大模型语音包（体积与授权风险） | 不做 |

### 2.3 决赛演示前的最小验收清单

1. 只用键盘：Tab 能到语音按钮，Enter 开启，听到问候；Tab 能到输入框并输入。
2. 语音模式开启后，助手只说一遍；按 Esc 立即停止。
3. 点“语速”循环四次回到“标准”，刷新后保持。
4. 打开纸规格弹层，输入 200×280，应用后 chip 显示“自定义 200×280”；输入 100×150 有中文错误提示；用 Tab 反复切换，焦点不跑出弹层，关闭后回到“纸张”按钮。
5. 提交构建后能听到当前阶段的具体动作（如“正在解析函数与关键点”“正在生成讲解音频”），完成时听到“建模完成，产物已经生成”。

## 3. 触觉板尺寸：已经自由到什么程度

- 可选目录：A5 / B5 / 16K / A4 / B4 / A3；自动模式按盲文行数与宽度选最小可容纳规格。
- 自定义：短边 ≥148 mm、长边 ≤420 mm、面积 ≥A5；保留横竖方向；越界在分析阶段就返回 400，不会进入几何层。
- 自定义尺寸同样走完整的 JSON Schema → 语义校验 → 布局 → STL → 合规检查，不是“只改个标签”。
- **尚未支持**：超过 A3 的分块打印与拼接标记；非矩形/圆角/装订孔；打印机可用幅面探测（目前靠用户自己确认热床尺寸）。

## 4. 智能体架构：哪些是真的瓶颈

### 4.1 现有结构（值得保留）

- **五段链路**：多模态理解 → 语义中间层 → 中文盲文编码 → 几何/STL → 合规检查。第 2–5 段纯确定性，可回归、可复现。
- **语义闸门**：`schema.py` 同时做 JSON Schema 与内置语义校验，模型输出进不了几何层。
- **证据链**：每块板输出 `diagram.json`、`braille_map.md`、`compliance.json`、`manifest.json`（含哈希），可追溯。
- **本地兜底**：无模型时走规则解析，断网也能出图。

### 4.2 真正的瓶颈

| 瓶颈 | 现象 | 风险 | 建议 |
|---|---|---|---|
| 构建串行 | `BUILD_LOCK` 全局互斥，`ThreadingHTTPServer` 收到并发请求也只能排队 | 多人同时演示时第二个用户等到超时 | 赛后换任务队列（SQLite 队列或 Redis + worker）；决赛前只做“排队中”提示 |
| 任务不持久 | 构建线程在进程内，重启即丢 | 现场误重启导致作业消失 | 已加启动恢复：中断任务标记为失败、给出重试提示；真正续跑仍需持久队列（赛后） |
| 观测缺失 | 只有 `print()` 与 `job.json` | 出错只能翻日志 | 赛后加结构化日志（JSON 行）与 `/api/metrics` |
| 模型层失败分级粗 | 超时/限额/格式错误都落到同一句“失败” | 用户不知道能不能重试 | 赛后按错误码分级，给出不同话术与重试建议 |
| 前端单文件 | `app.js` 5340 行，事件与状态耦合 | 改一处容易碰坏另一处 | 赛后按“会话 / 纸张 / 语音 / 编辑器”拆模块，加 DOM 级测试 |
| 草稿版本漂移 | 旧草稿在新版重建可能语义变化 | 答辩演示与提交材料不一致 | 赛后给草稿记录 `software.version`，版本不符时提示重建 |
| 3D 外部依赖 | TokenHub/文生 3D 有超时与费用 | 现场网络不稳 | 决赛前固定走本地几何链路演示，外部服务只作为加分项 |

### 4.3 架构升级路线（赛后）

1. **任务层**：`POST /api/build` 只入队，worker 串行消费；状态机 `queued → building → done/failed`。
2. **观测层**：每个阶段记录 `duration_ms`、`input_hash`、`output_hash`、`issue_counts`，落到 `metrics.jsonl`。
3. **评测层**：把四层准确率固化成脚本——理解层用固定语料、编码层用人工读校表、几何层用合规检查、实测层用盲测记录。
4. **前端层**：拆模块 + 用 Playwright 做 5 条关键路径回归（首页、函数、机械臂、纸规格、语音开关）。
5. **部署层**：把单机脚本升级为容器 + 反向代理 + 健康检查，保留离线包作为兜底。

## 7. 验收口径

- 新增改动必须有对应测试或可复现命令；没有验证的不写“已完成”。
- 对外只引用实测通过的数字，不用静态测试方法数冒充通过数。
- 盲文正确性仍以人工读校为准；本次改动不影响任何盲文编码，故不改变既有结论。
