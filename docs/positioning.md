# 相对通用多模态大模型，触见的独特优势

## 一句话

通用多模态大模型能“生成一个看起来像 3D 的模型”；触见要交付的是**一块能打印、能触摸、能讲课、能复核的触觉教材**。前者停在屏幕里，后者走到打印机和盲文阅读者手里。

这不是“我们的模型更强”，而是**模型之后那一段**不同：语义中间层、确定性几何内核、触觉标准检查、制造证据链和人在回路。

## 一、先把问题说准

“大模型可以 3D 建模”通常指三类能力：

1. 生成一段 3D 脚本或 CAD 代码；
2. 生成一个带纹理的三角网格，用于渲染；
3. 生成 Gaussian Splat / NeRF 一类视图表示。

它们擅长“看起来对”，但不天然保证：

- 网格水密、法线一致、可切片；
- 尺寸精确到毫米，且 A5 板能放进打印机；
- 线宽、点径、标签净空适合手指触摸；
- 阅读顺序、盲文、图例和讲解词符合教学场景；
- 同样的输入每次得到同样的文件；
- 失败时说“做不了”，而不是编一个看似合理的模型。

触见把这些问题拆开：**大模型负责理解，确定性内核负责几何，标准检查负责放行，清单与哈希负责复核。**

## 二、逐项对比

| 维度 | 通用多模态大模型直接生成 3D | 触见 TouchLearn |
|---|---|---|
| 最终产物 | 渲染用 mesh、点云或截图 | 二进制 STL + 触觉预览 SVG + 合规报告 + 音频页 + 二维码 + 打印说明 |
| 尺寸 | 相对比例，常需二次缩放 | A5 148 × 210 mm，内容区 132 × 142 mm，毫米级布局 |
| 网格质量 | 不保证水密、流形、法线 | 水密检查、体积为正、包围盒与板厚校验 |
| 触觉约束 | 不涉及 | 最小线宽、盲文点径与间距、标签净空、腕部间距、阅读顺序 |
| 可复现 | 采样随机，难复现 | 同一输入 + 同一版本 → 同一 STL，可用 SHA-256 复核 |
| 可审计 | 黑盒，难以解释 | `manifest.json`、`decision_trace.json`、PASS / DEVIATION / NEEDS_REVIEW |
| 可修改 | 重新写提示词，结果漂移 | 语义草稿和图形编辑器，改的是结构，不是碰运气 |
| 失败行为 | 容易“编一个看起来对的” | 结构化不了就明确拒绝；空电路、扫描 PDF 都会说实话 |
| 运行成本 | 通常依赖 GPU | 服务端 CPU 即可，理解走 API，离线也能跑模板 |
| 交付闭环 | 导出模型就结束 | STL、图例、音频、二维码、打印参数、合规报告一起交付 |

## 三、五条真正的护城河

### 1. 语义中间层，而不是一次性 mesh

用户确认的不是一张图，而是一份可编辑的结构：函数解析式与视窗、机械臂自由度与连杆、电路元件与回路、场景图块与阅读顺序。结构错了可以改结构；mesh 错了只能重抽卡。

电路示例最能说明问题：拖动灯泡不会产生悬空导线，因为导线由元件位置确定性重算；说“把灯泡换成电动机”，改的是语义模型，不是让模型重新画一遍。

### 2. 确定性几何内核

大模型不参与毫米坐标和 PASS/FAIL。表达式、布局、网格、STL 都由本地代码计算，因此：

- 同一份结构可以重复构建；
- 每个产物有 SHA-256；
- 合规结论可以逐条追溯到规则；
- 出问题能定位到具体模块，而不是“模型这次没画好”。

### 3. 触觉与无障碍标准被写成代码

普通 3D 模型追求视觉真实；触觉教材追求**手指能分辨、阅读顺序正确、标签不打架**。触见把线宽、点径、间距、净空、板厚、腕部空间等约束写成检查器，输出 PASS、工艺偏离和待人工复核项，而不是一句“看起来不错”。

### 4. 从文件到课堂的完整交付链

一块板子要能用，不止一个 STL：

- `model.stl`：切片软件直接打开；
- `preview.svg`：和 STL 同源的触觉预览；
- `compliance.md/json`：哪条过、哪条偏、哪条要人看；
- `audio.html` / `narration.wav`：扫码听讲解；
- `qr_card.svg` / `qr.png`：贴在图例卡上；
- `README.txt`：摆放方向、支撑、打印参数；
- `manifest.json`：版本、输入、产物哈希、已知限制。

通用大模型通常停在第一项。

### 5. 人在回路，而不是一键抽卡

触见先给草稿，用户确认后才构建；电路可以直接拖、改标签、切换开关；函数改了解析式会重算视窗和关键点；识别不出电路时不会偷偷塞一个默认电路。**可纠错**比“一次生成很惊艳”更适合教学和制造。

## 四、大模型在我们的系统里做什么

我们不是排斥大模型，而是把它放在合适的位置：

- 图片、PDF、自然语言 → 结构化草稿；
- 自然语言 → 电路编辑指令；
- 复杂场景 → 图块、标签、阅读顺序；
- 失败时降级到关键词、正则和 8 个离线模板。

它负责“看懂”，不负责“量准”。这也是为什么服务端不需要 GPU：理解在远端 API，几何在本地 CPU。

## 五、怎么在答辩里证明

不要只说“我们更准”，现场做三件事：

1. **同一请求构建两次**，打开两个作业的 `manifest.json`，对比 `model.stl` 的 SHA-256 一致；
2. **打开合规报告**，指出 PASS / DEVIATION / NEEDS_REVIEW 分别对应哪条规则，而不是一句“模型觉得可以”；
3. **在作业页点“校验产物完整性”**，现场核对 manifest 里的哈希与磁盘文件一致。

再加一句边界：“我们还没有完成实体打印和盲人用户测试，所以不宣称触觉可读性已经被验证。” 这比夸大更可信。

## 六、还缺什么

护城河不是一天挖完的。当前明确的缺口：

- 实体打印验证：尺寸、层高、喷嘴、材料对触觉效果的影响；
- 盲人用户测试：可读性、阅读顺序、讲解词是否真的有用；
- 更多标准：不同国家/地区的触觉图形规范；
- 中文盲文：当前使用 UEB 字母与阿拉伯数字，尚未实现 GF 0019-2018；
- 更多图种与更细的语义编辑：目前电路最完整，其他场景还在追赶；
- 真实课堂的长期使用数据。

这些缺口写在 `manifest.known_limitations` 和提交材料里，不藏。

## 七、可复用的答辩口径

**30 秒版**

> 通用大模型可以生成一个看起来像 3D 的模型，但它不保证水密、不保证毫米尺寸、不懂触觉标准，也不能复现。触见把大模型限制在“理解”这一步，后面用确定性内核生成可打印的 A5 触觉板，再用标准检查、合规报告和 SHA-256 清单把结果锁住。我们交付的不是一张图，是一套能打印、能扫码听讲、能复核的教学材料。

**3 分钟版**

> 第一，我们有语义中间层，用户改的是结构，不是重新抽卡；第二，几何是本地算的，同一输入同一哈希；第三，触觉标准写成了检查器，PASS/FAIL 可追溯；第四，交付链从 STL 一直到音频、二维码和打印说明；第五，识别不了就拒绝，不编。我们还不敢说触觉可读性已经验证，实体打印和盲测是下一步。

## 八、产品上已经落地的证据

- 作业页新增“制造证据”卡片：语义来源、几何内核版本、STL SHA-256、合规判定；
- 新增 `GET /api/jobs/<id>/verify`：逐文件核对 manifest 哈希，发现截断或篡改；
- 电路编辑器：拖动、改标签、切换开关、自然语言指令、图片识别；
- 函数视窗联动：改解析式重算窗口与关键点，裁切比例可见；
- 191 项测试覆盖几何、标准、路由、服务端、电路、函数窗口与产物校验。

这些不是 PPT 里的概念，是仓库里可以跑的代码。
