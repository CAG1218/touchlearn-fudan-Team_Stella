# Fix Report - TokenHub 照片级 3D 重建接入

日期：2026-11-03

## 一、背景

用户已有腾讯云 TokenHub 的 API Key（文本模型已在使用），希望照片级 3D 重建直接复用同一个 Key，不再单独申请 Tripo / Meshy。TokenHub 的 3D 接口与文本接口走同一个网关，但提交协议不同：

- 提交：`POST /v1/api/3d/submit`
- 查询：`POST /v1/api/3d/query`
- 鉴权：`Authorization: Bearer <API_KEY>`
- 状态：`queued` / `in_progress` / `completed` / `failed`

## 二、Bug 描述

首次真实提交返回 HTTP 200，但任务状态为 `failed`，且 `id` 为空：

```json
{
  "id": "",
  "request_id": "16f57ce0-...",
  "object": "3d_job",
  "status": "failed",
  "error": {
    "message": "ResultFormat为glb不在支持的模型格式列表[OBJ, GLB, STL, FBX, USDZ]内。",
    "type": "api_error",
    "code": "InvalidParameterValue.InvalidResultFormat"
  }
}
```

前端只看到“TokenHub 没有返回任务编号”，真实原因被吞掉。

## 三、问题根因

1. **`result_format` 必须大写**。官方示例里写的是小写 `obj`，但服务端枚举实际严格区分大小写，只接受 `OBJ / GLB / STL / FBX / USDZ`。
2. **失败响应仍是 HTTP 200**。原适配器只检查 `payload["id"]` 是否存在，没有先判断 `status == "failed"` 或 `error` 字段，导致把参数错误误报成“没有任务编号”。

## 四、尝试记录

### 尝试 1：沿用文档示例的小写 `glb`

- 结果：失败
- 原因：接口返回 `InvalidParameterValue.InvalidResultFormat`，说明枚举大小写敏感。

### 尝试 2：改为大写 `GLB`，并补充失败分支

- 结果：成功
- 原因：任务正常创建，返回任务编号并进入 `queued`。

### 尝试 3：在失败分支里解析嵌套错误信息

- 结果：成功
- 原因：`error` 可能是对象或字符串；提取 `message` / `code` 后，后续再出现参数错误时能直接看到服务端原文。

## 五、最终方案

### 1. 新增 TokenHub 适配器

`src/touchlearn/agent/reconstruct.py`

- `provider_name()` 识别 `tokenhub`、`hy-3d-*`、`hunyuan-*` 等别名。
- `provider_model()` 默认 `hy-3d-3.1`，可用 `TOUCHLEARN_3D_TOKENHUB_MODEL` 或 `TOUCHLEARN_3D_MODEL` 覆盖。
- `provider_key()` 在 TokenHub 下依次读取：
  1. `TOUCHLEARN_3D_TOKENHUB_KEY`
  2. `TOUCHLEARN_3D_KEY`
  3. `TOUCHLEARN_LLM_KEY`（与文本模型共用同一个 Key）
- `_tokenhub_submit()`：
  - `result_format` 固定大写 `GLB`
  - `enable_pbr=true`
  - HY-3D 模型追加 `generate_type=Normal`、`face_count`
  - Tripo 模型改用 `input` 字段
  - 先判断 `status=failed` / `error`，再取任务编号
- `_tokenhub_reconstruct()`：
  - 轮询 `/v1/api/3d/query`，请求体为 `{"model": ..., "id": ...}`
  - 兼容 `data` / `result` 为对象或列表
  - 下载 GLB 与预览图，交给本地 GLB 解析器
- 图生 3D 不允许 `prompt` 与照片同时提交，因此 TokenHub 路径不转发 prompt；文字里的高度、底座、留白、盲文与二维码位仍由本地确定性后处理执行。

### 2. 配置

```dotenv
TOUCHLEARN_3D_PROVIDER=tokenhub
# 留空时复用 TOUCHLEARN_LLM_KEY
TOUCHLEARN_3D_KEY=
TOUCHLEARN_3D_MODEL=hy-3d-3.1
TOUCHLEARN_3D_FACES=300000
TOUCHLEARN_3D_TIMEOUT=600
TOUCHLEARN_3D_POLL=4
```

可选模型：

- `hy-3d-3.1`：质量优先，默认
- `hy-3d-express`：更快
- `tripo-3d-3.1`：走 TokenHub 的 Tripo 通道

### 3. 文档与示例同步

- `.env.example`、`deploy/.env.example`：默认 provider 改为 `tokenhub`，补充 `TOUCHLEARN_3D_FACES` 与 Key 复用说明
- `render.yaml`：新增 `TOUCHLEARN_3D_FACES`
- `README.md`、`docs/deploy.md`、`deploy/README.md`、`docs/submission.md`：补充 TokenHub 配置、6 MB 照片上限、prompt 限制

### 真实端到端调用

用一张生成的木制玩具小车照片提交 `hy-3d-3.1`：

```text
任务 ID     1509216059885764608
耗时       约 219 秒
输出        model_textured.glb + thumbnail.png
网格        300,000 三角面，1 material，3 textures，has_uv=true
GLB 解析    0.7 秒
```

再用本地 `compose_printable` 生成可打印模型：

```text
总三角面     304,456
水密         true
外形尺寸     161.28 × 168.04 × 86.36 mm
打印体积     220 × 220 × 250 mm（通过）
底座         圆角矩形 161.28 × 168.04 × 4.5 mm
盲文         标题 + 2 个特征名牌，GF 0019-2018
二维码位     30 mm
```

说明 30 万面的 AI 网格可以在秒级完成解析、缩放、加底座和盲文，并保持水密可打印。

## 七、遗留与边界

- TokenHub 单张照片上限约 6 MB，超过时在本地直接拒绝，不上传。
- 图生 3D 不能同时提交 prompt 和照片，姿态类文字编辑不会转发，报告中如实标注。
- 服务端排队时间不稳定，默认超时 600 秒；超时不会删除已提交任务，任务 ID 24 小时内有效。
- 重建网格不保证水密。水密失败时仍保留纹理 GLB，但会明确提示无法直接生成可打印 STL。
