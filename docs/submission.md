# 初赛提交清单与答辩口径

本文把“仓库里已经有什么”和“提交前还需要准备什么”分开。具体截止时间、文件格式和平台要求**以官方通知为准**，本文不臆造日期。

## 1. 一句话与三句话

**一句话**：触见 TouchLearn 是一个把多模态 STEM 学习材料转成可打印触觉产物的智能体——先理解、再确认、后生成、最后做标准检查。

**三句话**：

1. 用户上传图片、PDF、TXT/JSON、STL/OBJ 或直接描述需求，智能体先给出可修改的结构草稿，而不是直接“描图”。
2. 确认后由确定性几何内核生成 A5 触觉板或立体模型，输出 STL、预览、合规报告、中文音频和二维码；大模型不参与毫米坐标和 PASS/FAIL。
3. 当前已跑通函数、机械臂、三维、通用场景、电路可视化编辑五条链路，8 个场景模板全部通过检查，188 项测试通过；但**尚未实体打印，也尚未完成盲人用户测试**。

## 5. PPT 结构（10 页）

1. 封面：项目名、队名、一句话；
2. 问题：盲人学生如何读 STEM 图；现有方案的三个缺口；
3. 洞察：描图不等于理解，语义结构才是可迁移的；
4. 方案：多模态输入 → 路由 → 草稿确认 → 确定性几何 → 合规检查；
5. 通用性：四类入口、8 个场景模板、场景 JSON、示例不是边界；
6. 模型接入：多家 OpenAI 兼容 API、视觉/文本分工、离线降级、密钥不外泄；
7. 案例 A：机械臂，重点讲腕部放大板和两种输出模式；
8. 案例 B：函数，重点讲系数驱动、关键点计算、自动视窗；
9. 证据：188 项测试、8 个模板无 FAIL、STL 水密与尺寸；明确“未打印、未盲测”；
10. 价值、路线图与团队：打印验证、盲测、更多图种、音频上线。

第 9 页不要把“测试通过”说成“用户验证通过”。这是两件事。

## 6. 答辩可能被问到的问题

**Q：这不就是给几个大模型 API 套壳吗？**

A：模型只做理解，不碰几何。分类、读图、抽取表达式和生成归一化场景可以由模型完成；毫米坐标、碰撞、三角化、水密和 PASS/FAIL 全部是本地确定性代码。换一家模型，STL 不变；模型胡编一个坐标，本地校验会拒绝。我们的工作量在语义契约、四种布局引擎、通用场景编译器、标准检查和可追溯产物上。

**Q：为什么只有两个案例？**

A：两个是**基准案例**，不是产品边界。通用场景编译器支持 8 个离线模板和任意场景 JSON，覆盖电路、流程图、几何、坐标系、路线、柱状图、细胞；函数和机械臂是两条专用高精度链路。演示时会现场输入一个没写死的电路需求，证明不是按关键词回放。

**Q：任意图片都能生成吗？**

A：不能，我们也不这么宣称。可结构化的示意图可以；照片级还原、真实尺寸测量、扫描 PDF 无文字层、无法结构化的散文会被明确拒绝或要求补充。系统不会为了出图而编造结构。

**Q：盲人能读懂吗？**

A：还没有做正式盲测，所以不能说“能读懂”。我们把可读性变成可检查的约束：最小线宽、标签净空、盲文点径、腕部间距，并写了可执行的盲测方案。下一步是打印和测试，用数据回答。

**Q：为什么不用大模型直接生成 3D？**

A：大模型可以帮我们提取语义，但布局和几何需要确定性和可解释性。评委可以问“为什么这个标签在这里”，`decision_trace.json` 能回答；端到端生成很难给出同等程度的可追溯性。

**Q：成本多少？**

A：A5 PLA 板材料成本低，具体数字取决于当地耗材价格和打印服务报价。我们没有做批量报价，不在答辩里编一个数。可以说明“单块板实体体积约 95–97 cm³，按 PLA 密度折算约 120 g 实心等效；15–20% 填充时实际耗材更少”，这是从网格体积算出来的，不是报价。

**Q：二维码里是什么？**

A：当前作业会自动生成指向本地音频页的二维码和播放页；公开演示前需要把 `--public-url` 设成手机能访问的地址，并做三台手机实测。链接不稳定就不放二维码，不在台上赌网络。

**Q：数据隐私怎么办？**

A：默认本地运行，产物写本机 `outputs/`。密钥只在环境变量或 `.env`，不写入作业目录，状态接口只返回 `has_key`。只有用户主动配置模型时，文字或图片才会发给对应服务；不配置就完全离线。

**Q：和现有触觉图工作相比呢？**

A：现有工作更多关注单张图的手工设计或通用触觉图形生成；我们的差异是把“多模态理解 + 语义契约 + 多布局引擎 + 可打印性门禁 + 标准证据 + 决策轨迹”做成一条可复现的编译链。这个比较需要文献支撑，答辩时只讲我们实际做的，不贬低别人。

## 7. 声明口径

可以说：

- “函数、机械臂、三维、通用场景、电路编辑五条链路端到端构建通过”；
- “8 个场景模板全部通过检查，无 FAIL”；
- “188 项测试通过”；
- “STL 水密、体积为正、尺寸 148 × 210 × 3.8 mm”；
- “可打印性检查 PASS”；
- “同一输入可复现相同 STL”；
- “大模型可替换，未配置时离线降级”；
- “盲测方案已写好，尚未执行”。

不能说：

- “已被盲人用户验证”；
- “可以直接上课使用”；
- “支持任意 STEM 图片”；
- “已实体打印并验证”；
- “二维码音频已上线公网”；
- “成本低于 X 元”（没有报价）；
- “逐条符合 GB/T 40142”（正文未公开，只核对了公开摘要）；
- “和某产品相比更好”（没有对比测试）。

## 9. 评审视角的自检

1. **这是不是一个真问题？** 盲人学生读 STEM 图确实存在结构性障碍，不是伪需求。
2. **这是不是一个真方案？** 有多模态输入、路由、草稿确认、四种布局链路、几何、标准检查、产物，不是只有概念图。
3. **证据够不够？** 代码、测试、STL、报告、轨迹、标准证据表都在仓库里，可复现；用户证据尚未完成，如实说明。
4. **团队能不能继续做？** 路线图有优先级和验证方式，不是空话。

第 3 个问题最容易被扣分。不要用“我们相信”替代“我们测过”。
